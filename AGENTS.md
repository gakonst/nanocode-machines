# nanocode-machines

`nanocode-mpp` (src/bin/nanocode-mpp.rs) is the Nanocode CLI with Codex and Claude paid per request over MPP sessions through [mpp-rs](https://github.com/tempoxyz/mpp-rs) instead of a ChatGPT or Claude subscription login. It only wires the two SDKs together: `nanocode_cli::run_with` runs the unchanged Nanocode TUI and `exec`, including the CLI's own durability defaults, and this crate adds no durability, library or other surface. Keep generic logic in the SDKs: provider-neutral hooks in gakonst/nanocode and payment logic in mpp-rs.

- `ModelClients::openai_endpoint` and `claude_endpoint` build Nanocode's own Codex and Claude clients for the proxies behind `Mpp`, a `nanocode::http::Layer`. Nanocode keeps building the headers, reading response metadata, mapping errors and decoding SSE; the layer only pays, running mpp-rs's 402 flow with `mpp::client::send_with_exchange` (tempoxyz/mpp-rs#588) over the layer's `Next`, so every attempt goes out through Nanocode's client. Request failures keep the error Nanocode's client reported, including whether a request was retryable, timed out or was never sent; payment failures are not retryable. Responses over MPP are HTTPS with full history replay.
- Each service gets its own wallet clone with `with_sqlite_session_store` (tempoxyz/mpp-rs#589): mpp-rs's MPPx-compatible channel store at `$TEMPO_HOME/wallet/channels.db` (default `~/.tempo/wallet/channels.db`), namespaced by service origin, so each service reuses its channel across processes. `NANOCODE_MPP_DEPOSIT` sets the session deposit and top-up in base units (default 2 MACH, dozens of Codex requests); the proxies send no `suggestedDeposit`.
- Prepaid vouchers skip the 402 round trip. The proxies' OpenAI and Anthropic session challenges are reusable (mppx `reusableChallenges`, wevm/mppx#1063, tempoxyz/mpp-proxy#407): they stay valid for later requests to the same route until they expire, and each request is charged its own price. With `with_session_prepaid_requests(PREPAID_REQUESTS)` (tempoxyz/mpp-rs#583), after one paid request the provider keeps that many requests' worth of balance, at the latest price, above the receipt's `spent` and sends the voucher with the next request. A `402` resends the request unpaid and falls back to the normal flow. With a top-up amount set, the provider tops the channel up in the background once its deposit no longer covers that prepaid balance plus the next request (tempoxyz/mpp-rs#585 through #587); vouchers are signed while the top-up runs.
- The CLI spawns the warm-up on its runtime: `TempoAccountsProvider::preconnect` sends each proxy an unpaid probe that opens the connection and warms the proxy (its isolate and tokenizer), then restores the selected session channel from the store and chain without paying (tempoxyz/mpp-rs#584, #589), so the first paid request only waits for its 402.
- Metered session responses are mppx SSE streams. The layer attaches a `nanocode::http::EventHook` to each response that hands every named event to `TempoSessionProvider::stream_event` (tempoxyz/mpp-rs#589): it answers `payment-need-voucher` with a voucher and resolves pending opens from `payment-need-voucher` and `payment-receipt`. Nanocode's decoders drop consumed events, and Claude treats mppx's generic `event: message` name as unnamed, as the SSE specification does.
- The status line the footer shows and `exec` prints comes from `TempoSessionProvider::spend`: per service, the server's charges from receipts this process paid, the last request's charge and the deposit left in those channels, in MACH.
- The wallet prefers MACH with `TempoAccountsProvider::with_preferred_currency`: a TIP-1034 session denominated in MACH wins, then a machine-token-enabled charge paid with MACH through the canonical swapper, then the first offer in Accept-Payment order (sessions before charges). This mirrors Mercator's MACH-first charge ordering.
- `OPENAI` and `ANTHROPIC` are the `serviceUrl` entries for `openai` and `anthropic` in https://mpp.dev/api/services. Since tempoxyz/mpp-proxy#394 their model routes offer only `tempo/session`, in USDC.e and MACH, with `unitType: request`, `feePayer` and `feeToken` USDC.e. `tempo/charge` in USDC.e and pathUSD with `machineTokenEnabled` is offered only to requests carrying a charge credential or an `Accept-Payment` header that ranks `tempo/charge` above `tempo/session`.
- The proxy charges a request-priced session stream once and passes the upstream bytes through with their event names and a `Payment-Receipt` header. Its `Server-Timing` header reports `mpp;dur`, the proxy's own time, and `upstream;dur`, the provider's time to response headers.
- `AcceptPaymentPolicy::Always` applies because the layer only receives the model endpoints configured on Nanocode; the management client's redirects are disabled. A retried model request pays for its own unit again.
- A model turn that fails with a retryable error after its retries stays pending in Nanocode's durability, so later prompts on that agent return `blocked by unfinished operation` until the host resumes it; the Nanocode TUI resumes it automatically. A connection that was never established is reported as unsent, so Claude retries it instead of treating its outcome as unknown.
- Install with `cargo install --path . --bin nanocode-mpp --locked`; `/reload` re-executes it from PATH. The CLI rejects `--gateway` because the Codex client is supplied.

## MACH sessions

Since T12 (mainnet 2026-10-13), TIP-1095 checks a TIP-1034 channel's TIP-403 policy on the logical payer-to-payee path and refunds the payer without it. A MACH session is therefore an ordinary TIP-1034 channel in MACH to a payee on MACH's recipient policy 582. tempoxyz/mach#93 added the MPP proxy payee `0xca4e835F803cB0b7C428222B3A3B98518d4779Fe` to that policy.

- A MACH channel cannot pay its own gas. Sponsored opens pay gas in the challenge's `feeToken` (tempoxyz/mpp-rs#582), and unsponsored opens need `with_session_fee_token`.
- mppx `compose()` dispatched every session credential to the first session handler, so the proxy rejected MACH opens with a currency mismatch. tempoxyz/mpp-proxy#395 routes MACH session credentials itself; wevm/mppx#1060 fixes `compose()`.

## Development

- Do not add code comments, doc comments, README files, tests or test-only dependencies. The user maintains README files.
- Nanocode, its CLI (`nanocode-cli`) and mpp-rs are pinned by git revision; `nanocode` and `nanocode-cli` share one gakonst/nanocode revision, which must include `ModelClients::openai_endpoint`, and mpp-rs points at a tempoxyz/mpp-rs main revision that includes #581 through #589. If cargo cannot fetch a revision, set `CARGO_NET_GIT_FETCH_WITH_CLI=true`.
- Check with `cargo fmt --check`, `cargo check --bins` and `cargo clippy --all-targets`.
- The ignored `output/validation` consumer was written against the removed `MppLayer` library and no longer builds. Real payments spend the wallet's funds; run them only with the wallet owner's approval.
